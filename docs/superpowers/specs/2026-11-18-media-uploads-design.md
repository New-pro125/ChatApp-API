# Design — Phase 2.4 generic media upload pipeline

Status: approved by the human partner on 2026-11-18.

## 1. Context and intent

Phase 2.4 establishes a generic, reusable upload layer: the API authorizes an
upload, the client sends bytes directly to private S3-compatible storage, and a
ClamAV scan gate decides whether the object becomes usable. It deliberately does
not wire uploads into avatars, stories, or messages yet; those integrations
arrive in later units.

The current repository already installs `@aws-sdk/client-s3` and
`@aws-sdk/s3-request-presigner` and defines MinIO, bucket, and ClamAV services
in `docker-compose.yml`. No application configuration, core port, schema,
repository, or HTTP surface consumes them. `users.avatar_key` and
`stories.media_key` are client-supplied placeholders and remain unchanged.

Success means a verified user can upload a file within configured limits, get a
clean-scan-gated object, retrieve a short-lived signed download URL, delete the
object, and observe predictable errors when input, storage, or scanning fails —
without the server storing object bytes or trusting client-supplied keys.

## 2. Goals

- Server-generated object keys and short-lived presigned `PUT` URLs.
- Exact content-type and size enforcement at presign time and recheck at
  finalize time.
- Fail-closed ClamAV scanning with an explicit configuration bypass for local
  development and tests.
- Private bucket; download access only through authenticated API-issued
  presigned `GET` URLs.
- Layered errors, Zod validation, generated OpenAPI contracts, and integration
  tests against real PostgreSQL/Redis/MinIO.
- Configuration solely through `AppConfig`/`EnvironmentReader`; README and
  `.env.example` updated.

## 3. Non-goals

- Avatar/profile and story key migration (later units).
- Message attachments, thumbnails, image transforms, or media messaging (2.5).
- Public URLs, CDN integration, or anonymous object access.
- Multipart/resumable uploads; the default cap is 50 MiB.
- Per-device media encryption, quarantine admin UI, or asynchronous rescan
  workers.
- Storing private keys, shared secrets, or plaintext in media metadata.

## 4. Architecture

### 4.1 Module layout

Create `src/modules/media/` following the existing module conventions:

```text
media/
  media.container.ts
  media.module.ts
  media.types.ts
  data/
    postgres-media-object.repository.ts
    s3-object.store.ts
    clamav-virus.scanner.ts
    media-object.mapper.ts
  logic/
    entities/media-object-record.ts
    ports/media-object.repository.ts
    ports/object-store.ts
    ports/virus-scanner.ts
    media.service.ts
  web/
    dto/media.schemas.ts
    dto/media.openapi.ts
    routes/media.router.ts
    media.controller.ts
```

`MediaModule` is a child container of `AppContainer`. The object-store and
virus-scanner ports stay inside this module because no other module consumes
them in Phase 2.4. A later unit may publish a narrow core port for resolving
media download URLs.

### 4.2 Schema

Add `src/core/database/schema/media.schema.ts` and export it from the schema
barrel. Table `media_objects`:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` PK, `uuidv7()` | Generated by the API. |
| `owner_user_id` | `uuid` NOT NULL | FK to `users`, `ON DELETE CASCADE`. |
| `object_key` | `text` NOT NULL UNIQUE | Server-generated; 1–512 chars. |
| `content_type` | `text` NOT NULL | 1–128 chars; allowlist enforced in app. |
| `size_bytes` | `bigint` NOT NULL | Positive; cap enforced in app. |
| `sha256` | `text` NULL | 64 lowercase hex chars when finalized. |
| `status` | `text` NOT NULL | `pending`, `ready`, `quarantined`, `failed`. |
| `scan_signature` | `text` NULL | Sanitized ClamAV signature, max 512 chars. |
| `scan_error` | `text` NULL | Sanitized scan error, max 512 chars. |
| `created_at` | `timestamptz` NOT NULL | Mutable-row timestamp. |
| `updated_at` | `timestamptz` NOT NULL | Mutable-row timestamp. |
| `finalized_at` | `timestamptz` NULL | Set when ready or quarantined. |

All indexes and constraints are explicitly named. Indexes: owner + status, and
owner + `created_at` for future listing. Drizzle rows are mapped to
`MediaObjectRecord` in `data/`; Drizzle types never leave that layer.

### 4.3 Object-store adapter

`ObjectStore` exposes:

- `presignPut(objectKey, contentType, sizeBytes): Promise<PresignedUpload>`
- `presignGet(objectKey): Promise<PresignedDownload>`
- `head(objectKey): Promise<{ contentType: string; sizeBytes: number } | null>`
- `getStream(objectKey): Readable`
- `delete(objectKey): Promise<void>`

`S3ObjectStore` uses AWS SDK v3 with configured endpoint, region, credentials,
and `forcePathStyle` for MinIO. The bucket is private. Object keys have the form
`media/<ownerUserId>/<mediaId>.<ext>`, where `<ext>` is derived from a fixed
content-type-to-extension map. Client filenames never influence object keys.

Presigned `PUT` signs exact `ContentType` and `ContentLength` headers and a
short TTL. Presigned `GET` is issued only when the row status is `ready`.

### 4.4 Scanner adapter

`VirusScanner` exposes `scan(stream: Readable): Promise<ScanResult>` where the
result is `{ verdict: 'clean' }` or `{ verdict: 'infected', signature: string }`.

`ClamAvVirusScanner` connects to `CLAMAV_HOST:CLAMAV_PORT`, sends the
NUL-terminated `zINSTREAM\0` command, streams chunks prefixed with 4-byte
big-endian lengths, terminates with a zero-length chunk, and reads the
NUL-terminated reply. Replies begin `stream: `; a clean verdict is exactly
`stream: OK\0` and an infected verdict ends with ` FOUND\0`, with the signature
between those markers (spaces preserved). It enforces `CLAMAV_TIMEOUT_MS` and
caps stored signature text. Protocol framing is a pure helper so it can be
unit-tested without a live daemon.

When `MEDIA_SCAN_REQUIRED=false`, `MediaService` skips the scanner after the S3
`HeadObject` recheck and marks the object `ready`. This is the only bypass and
must come from configuration, never `NODE_ENV`.

## 5. HTTP surface

All routes use `DocumentedRouter`, bearer auth, the verified-email middleware,
and the `rl:media:` Redis rate limiter. Controllers parse Zod schemas and use
the injected `ApiResponse` service.

| Route | Request | Success | Purpose |
| --- | --- | --- | --- |
| `POST /api/media/uploads` | `{ contentType, sizeBytes }` | `201` | Create `pending` row and presigned `PUT`. |
| `POST /api/media/:id/finalize` | none | `200` | Recheck S3, scan, mark ready/quarantined, issue `GET` URL. |
| `GET /api/media/:id` | none | `200` | Return metadata and a fresh presigned `GET` URL for ready objects. |
| `DELETE /api/media/:id` | none | `204` | Delete object and row. |

`POST /api/media/uploads` returns:

```json
{
  "success": true,
  "data": {
    "mediaId": "...",
    "objectKey": "media/...",
    "uploadUrl": "https://...",
    "headers": { "Content-Type": "image/png", "Content-Length": "1234" },
    "expiresAt": "2026-11-18T12:00:00.000Z"
  }
}
```

`POST /api/media/:id/finalize` and `GET /api/media/:id` return:

```json
{
  "success": true,
  "data": {
    "mediaId": "...",
    "status": "ready",
    "contentType": "image/png",
    "sizeBytes": 1234,
    "sha256": "64 hex chars",
    "downloadUrl": "https://...",
    "expiresAt": "2026-11-18T12:05:00.000Z"
  }
}
```

Finalize may be retried while the row is `pending`. A second call on a
`ready`, `quarantined`, or `failed` row returns `409 MEDIA_NOT_READY`. A scanner
outage leaves the row `pending` so the client may retry later; an unrecoverable
storage or metadata error marks it `failed`. Delete removes the S3 object first
and the row second, so a storage failure leaves the row available for retry.

## 6. Error model

Add domain exceptions in `core/errors/domain.error.ts`, repository exceptions in
`core/errors/repository.error.ts`, and mappings in `ErrorMapper`:

| Code | Status | Meaning |
| --- | --- | --- |
| `MEDIA_SCAN_UNAVAILABLE` | 503 | Scanner unreachable, timed out, or protocol error. |
| `MEDIA_INFECTED` | 422 | Scanner returned `FOUND`; row becomes `quarantined`. |
| `MEDIA_NOT_READY` | 409 | Object is pending/quarantined/failed or already finalized. |
| `NOT_FOUND` | 404 | Missing media row or S3 object on finalize. |
| `VALIDATION_ERROR` | 400 | Invalid body, content type, or size. |

AWS SDK and socket errors are wrapped as repository/adapter exceptions. Raw
credentials, signed URLs, object bytes, scan signatures, and internal error
messages are never exposed to clients or logs. Zod details are preserved for
validation failures.

## 7. Configuration

Add `MediaConfig` and `ClamAvConfig` to `AppConfig`, read only via
`EnvironmentReader`:

- `MEDIA_BUCKET` (required), `MEDIA_REGION` (default `us-east-1`)
- `MEDIA_ENDPOINT` (default local MinIO URL), `MEDIA_ACCESS_KEY_ID`,
  `MEDIA_SECRET_ACCESS_KEY`, `MEDIA_FORCE_PATH_STYLE` (default `true`)
- `MEDIA_MAX_BYTES` (default `52428800`)
- `MEDIA_ALLOWED_CONTENT_TYPES` (CSV; default images, video, audio, PDF, ZIP,
  and `application/octet-stream`)
- `MEDIA_PRESIGN_TTL_SECONDS` (default 300)
- `MEDIA_SCAN_REQUIRED` (default `true`)
- `CLAMAV_HOST` (default `127.0.0.1`), `CLAMAV_PORT` (default `3310`),
  `CLAMAV_TIMEOUT_MS` (default 10000)

Update `.env.example` and README. Required values fail fast at boot.

## 8. Security invariants

- Device identity and user id come only from the access token; ownership is
  never accepted from request bodies.
- Object keys are generated server-side and cannot be influenced by clients.
- Presigned `PUT` exact headers and finalize `HeadObject` recheck prevent type
  and size substitution.
- Only `ready` objects receive download URLs; infected objects are quarantined.
- Unverified users receive `403 EMAIL_NOT_VERIFIED` on every media route.
- No bucket credentials, object bytes, private keys, symmetric keys, or
  plaintext are stored in application tables or logs.
- Object deletion is owner-scoped; cross-user access returns `404 NOT_FOUND`.

## 9. Testing strategy

Follow TDD for each behavior.

Unit tests:

- config defaults and required-value parsing;
- content-type allowlist and size validation;
- object-key construction and extension mapping;
- presign option construction (exact headers and TTL);
- clamd INSTREAM framing and response parsing;
- error-code classification and sanitized details.

Integration tests (`tests/integration/media/media-api.test.ts`):

- `app.clearDatabase()` before fixtures;
- upload → presign → S3 PUT → finalize clean → signed GET;
- duplicate finalize, non-owner read/delete, missing row/object;
- invalid content type, oversized upload, mismatched finalize metadata;
- infected scan → `422 MEDIA_INFECTED`, no download URL;
- scanner outage → `503 MEDIA_SCAN_UNAVAILABLE`, row stays `pending`;
- `MEDIA_SCAN_REQUIRED=false` bypass → row becomes `ready`;
- delete removes row and object.

The scanner is rebound to a deterministic fake in tests. MinIO integration
tests use the running `minio`/`storage-init` services. A live ClamAV check may
be run manually with `docker compose --profile scan up -d`, but is not required
for the default suite.

## 10. Rollout and verification

- Generate and review the Drizzle migration; never edit an applied migration.
- Update README, `.env.example`, OpenAPI components, and error-code docs.
- Run `npm run verify`, `npm run db:check`, and a live smoke covering one success
  path plus validation, non-owner, infected, and scanner-outage error paths.
- Clean up temporary users, media rows/objects, processes, and containers started
  for verification.

## 11. Risks and deferred work

- MinIO presigned URLs depend on correct external endpoint/path-style config;
  misconfiguration fails fast at boot but local Docker networking must be
  validated in smoke.
- clamd `INSTREAM` keeps the object stream in memory-bounded chunks; the 50 MiB
  cap prevents unbounded buffering.
- Abandoned `pending` uploads are not automatically reclaimed in 2.4; a future
  lifecycle worker can add TTL cleanup.
- Avatar/story/message integrations will need a narrow core URL-resolving port
  and must not reintroduce client-supplied object keys.

## 12. Acceptance criteria

- All routes are documented with unique operationIds and validate input with
  the same Zod schemas used by OpenAPI.
- Private bucket, exact-header presigning, finalize recheck, fail-closed scan,
  and owner-scoped signed downloads are verified by automated tests.
- `npm run verify` and `npm run db:check` pass with docs trees present.
- Live smoke demonstrates one clean upload/download and at least four error
  paths; temporary data and processes are removed.
